GraphSync

In progress · C#/.NET, MQTT, MySQL

Problem
Analytics queries were four-way self-joins over tables of 16 and 20 million rows. Each took seven to eight seconds and appeared hundreds of times in the slow log.
What I am building
A graph traversal engine that keeps a memory-mapped compressed sparse row graph in step with MySQL over MQTT, replicated independently on each node. Edges cross user boundaries, so per-user sharding was ruled out.

16M and 20M rows7 to 8 s per query today

Video transcoding and HLS service

Node.js, TypeScript, Fastify, FFmpeg, BullMQ, Redis, Cloudflare R2

Problem
Video processing could not be allowed to block the main app.
What I did
Built a separate REST API that turns uploaded MP4 files into adaptive HLS streams from 144p to 1080p, with two-layer auth, rate limiting on every endpoint, and OpenAPI docs generated from Zod schemas. A structured code review found 17 issues, including one critical concurrency crash, and I fixed all of them. I also fixed Safari playback by converting 10-bit HEVC to 8-bit H.264.

39 passing tests17 review issues fixed
